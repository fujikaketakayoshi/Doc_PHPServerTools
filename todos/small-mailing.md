# 小規模メール配信 TODO

関連方針: [PRODUCT_STRATEGY.md](../PRODUCT_STRATEGY.md)

## 目的とMVP

QRスタンプラリー等の更新、新しい無料PHPツール、セキュリティ修正、有料サポートを、同意済みの登録者へ小規模に案内する。SMTPサーバー自体は作らず、購読者管理・配信予約・配信停止・送信ログを担うPHPアプリとする。

最初は登録者100〜1,000人、月1〜4回程度を想定し、自分の通知リストで内部運用する。到達率とバウンス対応の実績がたまるまで一般配布しない。

## 配送方式を決める

- [ ] 最初に使うSMTPサービスまたは推奨レンタルサーバーSMTPを決める
- [ ] 1分あたりの送信数と日次上限を決める
- [ ] cronの実行間隔を決める
- [ ] SMTP接続失敗、一時エラー、恒久エラーの再試行ルールを決める
- [ ] バウンスをWebhook、受信箱監視、手動取込のどれで処理するか決める
- [ ] 通知、更新情報、宣伝の送信元やリストを分ける方針を決める

## DNS・送信環境

- [ ] SPFを設定して検証する
- [ ] DKIMを設定して検証する
- [ ] DMARCを設定し、最初はレポートを確認できる状態にする
- [ ] SMTPサービスが求めるドメイン確認・Return-Path用レコードを設定する
- [ ] From、Return-Path、署名ドメインの整合を確認する
- [ ] Gmail等のテストアドレスでヘッダーと迷惑メール判定を確認する
- [ ] DNS設定手順を記録する

## 購読者管理MVP

- [ ] メールアドレス、登録日時、登録元を保存する
- [ ] 同意文面のバージョンと同意日時を保存する
- [ ] 未確認、購読中、停止、エラーの状態を管理する
- [ ] 確認メールによるダブルオプトインを実装する
- [ ] 推測困難な配信停止URLを発行する
- [ ] ワンクリック配信停止と再登録を実装する
- [ ] CSVインポート時に同意取得済みか確認させる
- [ ] CSVエクスポートを実装する
- [ ] 重複アドレスと大文字小文字の扱いを統一する

## 配信MVP

- [ ] 件名、テキスト本文、HTML本文の作成
- [ ] 送信者情報、登録理由、問い合わせ先、配信停止URLを自動挿入
- [ ] テスト送信
- [ ] 即時配信と予約配信
- [ ] 対象リストの選択と送信予定件数の確認
- [ ] 配信確定前のプレビュー
- [ ] 宛先ごとの配信キュー作成
- [ ] cronで10〜50件ずつ段階送信
- [ ] 同じキャンペーンの重複送信防止
- [ ] 成功、失敗、再試行、停止のログ保存
- [ ] 配信結果の件数集計

## 配信停止・法令対応

- [ ] 購読フォームのチェックを初期状態でオフにする
- [ ] 配信内容を具体的に説明した同意文面を表示する
- [ ] ダウンロード条件として購読を強制しない
- [ ] メール本文に送信者名、問い合わせ先、登録理由、停止URLを載せる
- [ ] `List-Unsubscribe` ヘッダーを付ける
- [ ] ワンクリック停止に必要なヘッダーと処理を実装する
- [ ] 停止済みアドレスを再インポートしても自動復活させない
- [ ] 特定電子メール法等に関する運用チェックを専門家または最新資料で確認する

## 到達率と障害対応

- [ ] 一時エラーは回数と間隔を制限して再試行する
- [ ] 恒久エラーのアドレスを自動停止する
- [ ] 連続失敗時に配信全体を一時停止する安全装置を付ける
- [ ] SMTP認証失敗や送信上限超過を管理画面に具体的に表示する
- [ ] メールアドレス等をログで必要以上に露出させない
- [ ] バウンス件数、停止件数、苦情の記録方法を決める
- [ ] セキュリティ通知は配布サイトと製品管理画面にも掲載する

## 内部運用から公開判断まで

- [ ] 自分の製品サイトに任意購読フォームを設置する
- [ ] 主要メールサービス宛てに少人数で初回配信する
- [ ] 送信速度を段階的に上げる
- [ ] 500人程度までの運用を目安に障害と到達状況を記録する
- [ ] DNS、SMTP、配信停止、失敗診断の動画を作る
- [ ] 問い合わせ原因をアプリ、SMTP、DNS、送信制限、受信側に切り分ける診断画面を作る
- [ ] 推奨環境で安定した後に配布版へ切り出すか判断する
