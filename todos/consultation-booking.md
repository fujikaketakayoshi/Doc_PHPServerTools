関連方針: [PRODUCT_STRATEGY.md](../PRODUCT_STRATEGY.md)

## 目的とMVP

個人事業者が自分のドメインで相談枠を販売し、Stripeで事前決済を受け付けられるようにする。最初は自分のPHPツール設置サポートに使用する。ZoomまたはGoogle Meetの固定URLを販売者が登録し、待機室を使う方式から始める。

## 仕様を確定する

- [ ] 最初の利用者を自分一人に限定した業務フローを書く
- [ ] 相談メニュー、所要時間、料金、準備時間の設定単位を決める
- [ ] 営業時間、休業日、臨時休止の設定方法を決める
- [ ] 予約変更、キャンセル、返金の初期ルールを決める
- [ ] タイムゾーンを日本時間固定にするか決める
- [ ] Stripe CheckoutとWebhookの利用方法を決める
- [ ] 決済失敗・途中離脱・Webhook遅延時の状態遷移を決める

## 販売者向けMVP

- [ ] 管理者ログイン
- [ ] 相談メニュー名、説明、時間、料金の登録
- [ ] 固定Zoom／Google Meet URLの登録
- [ ] 待機室必須の注意事項を設定画面に表示
- [ ] 曜日別の受付時間設定
- [ ] 個別の休業日・受付枠停止
- [ ] 前後10〜15分等の準備時間設定
- [ ] 予約一覧、詳細、決済状態の表示
- [ ] 手動キャンセルとメモ
- [ ] 予約・決済データのCSV出力

## 顧客向けMVP

- [ ] 相談メニューの選択
- [ ] 空き枠の表示
- [ ] 氏名、メール、必要最小限の相談内容入力
- [ ] 利用条件とキャンセル条件への同意
- [ ] Stripe Checkoutへの移動
- [ ] 決済完了後の予約確定画面
- [ ] 確定メールで日時と参加URLを通知
- [ ] 予約確認用の推測困難なURLを発行

## 二重予約と決済整合性

- [ ] 決済開始時に枠を10〜15分仮押さえする
- [ ] データベースの一意制約で同一枠の重複確定を防ぐ
- [ ] 仮押さえ作成をトランザクションで処理する
- [ ] Stripe Webhookの署名を検証する
- [ ] Webhookを複数回受信しても重複確定・重複送信しない
- [ ] 期限切れ仮押さえをcronで解放する
- [ ] 決済成功と予約確定がずれた場合の復旧手順を用意する
- [ ] Stripe上の決済ID・返金IDを記録する

## セキュリティ・運用

- [ ] 固定URL利用時の待機室、参加者確認、会議室ロックを案内する
- [ ] ホストより前の参加を禁止するよう案内する
- [ ] 参加URLは決済前の画面やHTMLソースへ出さない
- [！] Stripe秘密鍵を公開領域外へ保存する
- [ ] 予約日時、金額、メール送信、Webhook結果をログへ残す
- [ ] 個人情報の保管期間と削除方法を決める
- [ ] 特商法表示、利用規約、プライバシーポリシーを用意する
- [ ] バックアップと復旧を確認する
